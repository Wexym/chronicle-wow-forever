# Разработка

Как устроен аддон «Летопись» и как добавлять в него новое.

## Требования к окружению

- Клиент WoW Forever. Запускать аддон вне игры нельзя: проверяется вручную через `/reload`.
- Аддоны **BugSack** и **BugGrabber** для сбора ошибок Lua.
- Папку `Chronicle` удобно связать с `Interface\AddOns` символической ссылкой (junction), чтобы изменения были видны сразу: см. [README](../README.md#способ-2-через-git-если-планируете-обновляться-или-править-код).
- Номер интерфейса в `Chronicle.toc` (сейчас `16001`) проверяется в игре: `/dump select(4, GetBuildInfo())`.

## Структура

```
Chronicle/
  Chronicle.toc          номер интерфейса, SavedVariables, порядок загрузки файлов
  Locale/ruRU.lua        все строки интерфейса
  Core/Init.lua          пространство имён, БД, значения по умолчанию, миграции, реестр модулей, события
  Core/Utils.lua         время сервера и сбросов, ключи дней, форматирование чисел, денег и времени
  Core/Commands.lua      /chron и подкоманды, диагностика
  UI/Widgets.lua         общие элементы: кнопка, поля ввода, многострочное поле, список с прокруткой, диалоги
  UI/MainFrame.lua       главное окно, ряд вкладок, кнопка у миникарты
  Modules/*.lua          по одному файлу на вкладку (Players, Checklist, Stats, Journal, Alts,
                         Goals, Wishlist, Reminders, Stream, Hardcore, Wowhead, Settings)
```

Порядок загрузки задаёт `Chronicle.toc`. Порядок вкладок в окне повторяет порядок регистрации модулей (то есть порядок файлов в `.toc`); вкладка с признаком `right` (настройки) закрепляется справа.

## Правила кода

- Весь код на Lua, интерфейс — фреймы, созданные из Lua, шаблоны Blizzard (`BasicFrameTemplateWithInset`, `UIPanelButtonTemplate`, `InputBoxTemplate` и т. д.). Своей графики нет.
- **Глобальные** только `ChronicleDB`, `ChronicleCharDB`, `Chronicle` (пространство имён) и то, чего требует API: имена фреймов для `UISpecialFrames`, `SLASH_*`, `SlashCmdList`, `StaticPopupDialogs["CHRONICLE_..."]`.
- Не вызывать защищённые функции и не трогать защищённые фреймы Blizzard (это вызывает taint). Работа в бою допустима только для своих фреймов.
- Фреймы вкладки создаются при **первом открытии** вкладки, а не при входе в игру.
- Перед использованием функции API, которой нет в старых клиентах, проверять её наличие (`if C_Something and C_Something.Func then`); не вызывать то, в наличии чего не уверены. Команда `/chron diag` помогает это узнать.
- Обработчики частых событий (журнал боя, здоровье) должны быть лёгкими: сравнение и счётчик, без создания строк и таблиц.
- Комментарии на русском. В Lua-строках с путями обратные слэши удваиваются: `"Interface\\Icons\\INV_Misc_Note_01"`.

## Как добавить вкладку

1. Создайте файл `Chronicle/Modules/Имя.lua` и добавьте его в `Chronicle.toc` перед `Modules\Settings.lua`.
2. Зарегистрируйте модуль одним вызовом. Функция `create(frame)` вызывается при первом открытии вкладки:

```lua
local ADDON, ns = ...
local L = ns.L
local UI = ns.UI

local function Create(frame)
    UI.Placeholder(frame, L["my_tab_hello"])
end

-- ключ, ключ строки названия вкладки, иконка (необязательно), функция создания, опции
ns:RegisterModule("mytab", "tab_mytab", nil, Create)
```

3. Добавьте строку названия вкладки (и остальные) в `Chronicle/Locale/ruRU.lua`:

```lua
L["tab_mytab"] = "Моя вкладка"
```

Дополнительно:

- `ns:OnInit(fn)`: выполнится после загрузки БД (`ADDON_LOADED`), `ns:OnLogin(fn)`: при входе в игру (`PLAYER_LOGIN`), когда уже известен `ns.charKey`. Сбор данных и подписка на события регистрируются здесь, а не в функции создания вкладки.
- Опции `ns:RegisterModule(..., { right = true, icon = "..." })`: вкладка справа с иконкой.
- Если вкладка хранит данные, которые можно очистить в настройках, добавьте функцию в `ns.refresh.<ключ>`: она перерисует вкладку после очистки.

## Данные

Две переменные SavedVariables. Значения по умолчанию задаются **в одном месте** — `ns.defaults` и `ns.charDefaults` в `Core/Init.lua` — и подставляются при загрузке (`FillDefaults`): существующие значения не затираются.

`ChronicleDB` (аккаунт): `version`, `settings`, `minimap`, `characters` (сводка по каждому персонажу для «Альтов»), `players`, `checklist`, `checklistHistory`, `stats` (`days`, `months`), `journal`, `goals`, `wishlist`, `reminders`.

`ChronicleCharDB` (персонаж): `window`, `lastTab`, `checklist`, `session`, `stream`, `hardcore`, `timePlayed`.

Ключ персонажа — `Имя-Сервер`, ключ дня — `ГГГГ-ММ-ДД` по времени сервера. Дневные корзины статистики хранятся 90 дней, затем сворачиваются в месячные итоги.

**Изменение структуры:** поднимите `ns.DB_VERSION` и добавьте функцию в таблицу `migrations` в `Core/Init.lua`. Данные пользователей удалять без миграции нельзя.

## Локализация

Все строки интерфейса лежат в `Chronicle/Locale/ruRU.lua`. Таблица `ns.L` возвращает сам ключ, если строки нет, поэтому пропуск виден в интерфейсе. Чтобы добавить язык, создайте `Locale/enUS.lua` с теми же ключами, подключите его в `.toc` после `ruRU.lua` с проверкой `GetLocale()` и переопределите нужные ключи. Строки аддона содержат форматы (`%s`, `%d`): число и порядок аргументов должны совпадать.

## Проверка перед отправкой

1. `/reload`: окно открывается без ошибок во всех вкладках.
2. В BugSack нет новых записей после работы с изменёнными вкладками.
3. Все строки интерфейса добавлены в `Locale/ruRU.lua`.
4. Данные сохраняются после `/reload` и повторного входа.
